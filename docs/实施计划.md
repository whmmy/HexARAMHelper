# HexARAMHelper 实施计划 v4（定稿）

> 2026-09-24 定稿。背景见 [可行性研究报告.md](可行性研究报告.md)。
> v4 相对 v3 的关键修正（用户拍板）：**删除流派卡选择**及一切让用户"选流派/路线"的步骤；System 2 加载期产物改为「英雄作战上下文 ChampionContext」；**所有推荐统一为"3 个选项 + 理由"**；新增海克斯刷新(reroll)重识别与首次采样标定。

## 1. 产品定义（最终）

**一句话**：游戏加载时读双方阵容和我的英雄 → 智能模型预生成该英雄的海克斯/装备知识上下文 → 游戏内小模型按对局快照给建议：**出门装三选、每轮海克斯推荐、下一件三选、小件合成判断**——全部带理由，跟着已选海克斯和实际出装自动调整（如拿到"心之刚"→ 出门装建议自动变巨人腰带）。

**用户零输入**：不选流派、不点路线、不用热键。装备方向由 System 1 根据快照（已选海克斯 + 实际出装 + 敌方阵容）自动演化。

**明确不做**：游戏外版本摘要/meta 补课、AI 替用户做流派决策、敌方海克斯识别（搁置）、胜率数字展示（合规——只显示 S/A/B 档位和理由）。

**核心铁律：数据出事实，模型出判断**。版本答案只来自 OP.GG 天级刷新统计（英雄粒度），模型只做重排/适配/写理由，输出经 DD 装备库校验防幻觉 → 模型训练滞后不影响推荐时效。

## 2. 核心流程

```
[待机] →LCU ChampSelect→ [选人] 自动锁定英雄（骰子换人自动跟随）
→GameStart→ [加载] 读双方10人阵容 → System2 生成 ChampionContext（内存缓存）
→InProgress→ [游戏内]
    首轮海克斯界面（自动检测）→ OCR三选一 → System1 排序 → 用户点卡片（鼠标记账）
      → 自动推出门装三选（结合刚选的海克斯）
    每轮海克斯：检测→OCR→排序→记账；reroll 点击或内容变化 → 重新识别+推荐
    我死亡时 → 下一件三选（结合身上小件：合成 or 攒大件）
    敌方关键装备完成/KDA起飞 → 克制提示
→EndOfGame→ [结算] 自动重置
```

### ChampionContext（加载期 System 2 一次调用生成，紧凑 JSON ~1.5k token）
```json
{
  "augment_affinity":  [{"name":"贪欲束缚","bias":"ad","note":"..."}],
  "opening_items":     [{"combo":["鞋子","长剑"],"when":"标准"},
                         {"combo":["多兰盾"],"when":"对面poke多"},
                         {"combo":["巨人腰带"],"when":"已选心之刚"}],
  "build_paths":       {"ap":[...], "ad":[...], "tank":[...]},
  "component_rules":   [{"item":"巨人腰带","upgrade_to":"日炎","hold_when":"经济不足时先留着"}],
  "augment_item_links":[{"augment":"心之刚","shift":"出门装→巨人腰带，路线偏坦","reason":"..."}]
}
```
- `augment_affinity`：该英雄海克斯亲和 top15~20（OP.GG 排名 + 语义标签合成，带倾向标记）
- `build_paths`：内部多路线（AP/AD/坦），仅供 System1 参考，**不展示给用户**
- Schema 校验 → 失败重试 1 次 → 再失败降级规则版 Context（离线兜底）

### System 1 统一输出格式（所有建议）
```
[推荐1] 装备/海克斯名 —— 一句话理由（结合敌方构成/已选海克斯/身上小件）
[推荐2] ...
[推荐3] ...
```
调用时机与预算：首轮海克斯 1 + 出门装 1 + 每轮海克斯 3~4 + reroll 重推 0~1 + 死亡刷下一件 2~3 + 事件简评 1~2 ≈ **每局 8~11 次，硬上限 15**。

## 3. 交互实现

| 机制 | 实现 |
|---|---|
| 生命周期 | LCU 阶段状态机（ChampSelect→GameStart→InProgress→EndOfGame）自动驱动，无热键；仅留一个可选 overlay 显隐键 |
| 海克斯界面检测 | 仅游戏内每 2s 局部截图 + 模板匹配（几 ms 不跑 OCR）；连续 2 帧确认出现 / 3 帧确认消失（迟滞防误触） |
| 海克斯记账 | 只读鼠标钩子（WH_MOUSE_LL，不拦截不注入）：界面活跃窗口内，点击落点在卡片 A/B/C 矩形 → 记账"本轮已选 X"；台账常驻可见可纠错 |
| **reroll 重识别** | ① reroll 按钮区域纳入点击监听，点击立即主动重扫；② 界面活跃期间每 2s 轻量 OCR 比对卡片标题，内容变化即重新识别+推荐（双保险） |
| **首次采样标定** | 主窗口"开始标定"→ 海克斯界面出现时自动截屏 → 保存检测模板（三卡片+背景特征）、卡片矩形、reroll 按钮矩形 → 之后永久全自动；版本改版模板失效时提示重标定。分辨率自适应沿用参考项目 REGIONS 缩放做初值；开发期可用界面截图离线预制模板 |
| 出门装触发 | 首轮海克斯记账后自动推（若尚未买装备）；死亡复活自动刷下一件 |
| 兜底 | LCU 断连 → 主窗口手动输英雄（拼音模糊匹配，沿用参考项目）；AI 失败/无 key → 规则模式 |

## 4. 模型双槽位（百炼，界面独立配置）

| 槽位 | 用途 | 默认模型 | 频率 |
|---|---|---|---|
| System 2 | ChampionContext 生成、语义标签库离线生成 | qwen3.8-max | 每局 1 次 |
| System 1 | 快照建议器（三选项+理由） | qwen3.8-flash（¥0.8/¥2.7 每百万 token） | 每局 8~11 次 |

每槽位独立配置：模型名（预置 qwen3.8-max / qwen3.7-plus / qwen3.8-flash / deepseek-v4-pro / deepseek-v4.1-flash / kimi-k3 / glm-5.3 + 自定义输入）、API Key（仅存本地 settings.json，可选读环境变量 DASHSCOPE_API_KEY）、base_url（默认百炼 OpenAI 兼容端点）、温度、max_tokens、**测试连接按钮**。全局：AI 总开关、每局调用硬上限、费用仪表（本局/累计，单价可改）、超限或无 key 自动降级规则模式。任意 OpenAI 兼容平台均可换用（如一个槽 deepseek 一个槽 qwen）。

**成本**：~¥0.07~0.12/局，每天 10 把 <¥1.5；新用户免费额度覆盖数百局。

## 5. 三层数据栈

| 层 | 内容 | 来源 | 作用 |
|---|---|---|---|
| A 统计层 | 核心装/鞋子/出门装登场率+胜率、海克斯排名、技能加点 | OP.GG（Selenium 沿用参考项目，天级刷新；P1 尝试 XHR 探针降级纯 HTTP） | 版本货币 |
| B 事实层 | 装备/海克斯属性、效果、语义标签（减疗/魔抗/爆发/流派亲和） | Data Dragon 元数据 + System2 离线打标（229 海克斯，增量更新） | 防幻觉 + 规则引擎依据 |
| C 战局层 | 实时敌方出装/KDA/伤害构成、我的装备与技能等级 | Live Client Data API（127.0.0.1:2999，5s 轮询；P0 首日 dump 实测字段） | 适配输入 |

出装推荐流程：候选集 = 我的英雄 OP.GG 高频装备 ∪ DD 通用抗性/功能件 → 规则引擎按敌方构成打分（3 法师→魔抗↑，2 治疗→重伤↑）→ System1 候选内给三选+理由 → 装备名必须过 DD 校验才输出。

## 6. 资料库版本感知更新

1. 知道版本变了：LCU patch 号 + DD versions.json 每日检查
2. 知道内容变了：OP.GG 抽样校验（随机 3 英雄比对，差异→增量抓取）+ CommunityDragon 该模式海克斯定义集合 diff（新增/改名当天发现，P0 验证路径）
3. 执行更新：增量爬变动条目 → 语义标签只对新增项重生成 → 快照版本化 + GitHub 兜底
4. UI 数据面板常显"数据版本/最新版本" + 一键更新，全程后台无感

## 9. 风险登记

| 风险 | 对策 |
|---|---|
| 流派粒度翻译层质量（最大假设） | P0.5 先验证，不通过退化为"英雄粒度为主+联动仅规则" |
| Live API 该模式字段未实测 | P0 首日 dump allgamedata 验证，异常退化 LCU+OCR |
| 画面模板需采样、版本改版失效 | 内置标定引导；可离线预制；模板可配置 |
| reroll 后内容比对误判 | 仅界面活跃期比对+防抖；内容稳定后才确认记账 |
| 鼠标记账误判 | 台账常驻+纠错；窗口门控+迟滞 |
| OP.GG 反爬/模式轮换下线 | 快照+GitHub 兜底；XHR 探针 |
| 百炼模型名/价格变动 | 下拉可编辑+测试连接+单价可改 |
| qwen3.8-max 输出偏慢 | max_tokens 1500+紧凑 JSON；超时降 qwen3.7-plus 重试 |
| rapidocr 需 Python<3.13 | 锁 3.12 + uv |
