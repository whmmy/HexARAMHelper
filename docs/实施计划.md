# HexARAMHelper 实施计划 v4.2（定稿）

> 2026-09-24 定稿。背景见 [可行性研究报告.md](可行性研究报告.md)。
>
> **v4.2 相对 v4.1 的修订**（2026-09-24 晚用户反馈，已实装 P0 规则层）：
> 1. **触发模型双轨制**：从"事件驱动（死亡等）"改为「**定时快照 diff + 事件触发**」——Live 轮询每 5s 做状态签名比对（我方装备 / 金币档 250G 粒度 / 敌方装备 / 死亡态），签名变化即重算建议，不再只靠死亡触发；死亡 / 敌方关键装 / KDA 事件保留即时触发。P0 规则层重算零成本；P2 AI 模式在签名 diff 之上加调用间隔与预算守门（`triggers.periodic_recheck` 可关）。
> 2. **装备推荐从"下一件三选"改为「出装主线序列（金币感知）」**：按优先级给后续 2~3 件并标注价格与可买性（金币按序累计，够买第 1 件后剩余继续判第 2 件，兑现"钱够连买两件"场景）；小件合成线有目标时置顶。海克斯三选与出门装三选保持不变。
>
> **v4.1 相对 v4 的关键修正**（2026-09-24 计划评审 + 用户确认后合入）：
> 1. 修正 C 层数据描述："敌方实时伤害构成"**数据不存在**（Live API 无 per-player 伤害拆分），改为"敌方威胁画像（由英雄 + 装备推断）"；
> 2. 出装/海克斯时序确认：**先海克斯、后出门装**（用户确认），出门装触发改为显式两分支状态机，P2 明星验收场景前提成立；
> 3. 海克斯界面确认：**固定 3 张横排卡片 + reroll 按钮**，reroll 重扫保留；画面检测主信号改为"标题条 OCR + 229 库模糊匹配"，模板匹配退为预热/兜底；
> 4. 补回并**收窄**加点需求：只给"大概加点顺序"（静态，来自 OP.GG + ChampionContext），不做实时技能点计算、不加 abilities 轮询；
> 5. 新增层 0 确定性细则：`current_path` 状态（防路线漂移）+ 三类候选池构造函数（出门装/下一件/小件合成）；
> 6. `mouse_ledger` 复用参考项目已依赖的 `keyboard` 库（**移除 pynput**），保留 50ms 轮询兜底方案；
> 7. **不建**完整离线回放设施，改为 P0 内置 fixtures dumper（真机调测时自动落盘），后续开发用落盘数据 mock；
> 8. 数据新鲜度可见性（抓取日期 / 超龄黄标 / 数据版本号进 prompt）；P0.5 通过标准定死。

## 1. 产品定义（最终）

**一句话**：游戏加载时读双方阵容和我的英雄 → 智能模型预生成该英雄的海克斯/装备知识上下文 → 游戏内小模型按对局快照给建议：**出门装三选、每轮海克斯推荐、下一件三选、小件合成判断、建议加点顺序**——全部带理由，跟着已选海克斯和实际出装自动调整（如拿到"心之刚"→ 出门装建议自动变巨人腰带）。

**用户零输入**：不选流派、不点路线、不用热键。装备方向由层 0 的 `current_path`（从已购装备 + 已选海克斯确定性推断）+ System 1 在路线内三选共同决定。

**明确不做**：游戏外版本摘要/meta 补课、AI 替用户做流派决策、敌方海克斯识别（搁置）、胜率数字展示（合规——只显示 S/A/B 档位和理由）、实时技能点计算与加点偏离告警（只给静态顺序）、完整离线回放设施（只做 dump）。

**核心铁律：数据出事实，模型出判断**。版本答案只来自 OP.GG 天级刷新统计（英雄粒度），模型只做重排/适配/写理由，输出经 DD 装备库校验防幻觉 → 模型训练滞后不影响推荐时效。

## 2. 核心流程

```
[待机] →LCU ChampSelect→ [选人] 自动锁定英雄（骰子换人自动跟随）
→GameStart→ [加载] 读双方10人阵容 → System2 生成 ChampionContext（内存缓存）
→InProgress→ [游戏内]
    首个海克斯界面（自动检测）→ OCR三选一 → System1 排序 → 用户点卡片（鼠标记账）
      → 分支：未买装备 → 出门装三选（结合刚选海克斯）｜已买装备 → 转入下一件建议
    每层海克斯（CSV 三档 白银/黄金/棱彩 推断约 3 层，轮数与时间点 P0.5 实测记录）：
        检测→OCR→排序→记账；reroll 按钮点击 → 立即重扫；标题内容变化 → 重启识别+推荐
    我死亡时 → 下一件三选（current_path 内；身上小件 → 合成 or 攒钱）
    敌方关键装备完成/KDA起飞 → 克制提示
→EndOfGame→ [结算] 自动重置（秒退/掉线回大厅同样重置）
```

### 出门装触发状态机（v4.1 明确，前提：先海克斯后出门装）

| 触发时机 | 装备状态 | 动作 |
|---|---|---|
| 首个海克斯记账后 | 未购买任何装备 | 出**门装三选**（结合刚选海克斯，兑现"心之刚→巨人腰带"类联动） |
| 首个海克斯记账后 | 已购买 | **不再推开门装**，转入"下一件三选" |
| 每次死亡刷新 | 任意 | 下一件三选 |

### ChampionContext（加载期 System 2 一次调用生成，紧凑 JSON ~1.5k token）
```json
{
  "augment_affinity":  [{"name":"贪欲束缚","bias":"ad","note":"..."}],
  "opening_items":     [{"combo":["鞋子","长剑"],"when":"标准"},
                         {"combo":["多兰盾"],"when":"对面poke多"},
                         {"combo":["巨人腰带"],"when":"已选心之刚"}],
  "build_paths":       {"ap":{"items":[...],"skill_order":"主W副Q","note":"..."}, "ad":{...}, "tank":{...}},
  "component_rules":   [{"item":"巨人腰带","upgrade_to":"日炎","hold_when":"经济不足时先留着"}],
  "augment_item_links":[{"augment":"心之刚","shift":"出门装→巨人腰带，路线偏坦","reason":"..."}]
}
```
- `augment_affinity`：该英雄海克斯亲和 top15~20（OP.GG 排名 + 语义标签合成，带倾向标记）；"升级：X"型海克斯单独打标（决策语义是"升级哪件已购装备"而非"要不要"）
- `build_paths`：内部多路线，仅供 System1 参考，**不展示给用户**；每条路线带 `skill_order`（大概加点顺序）
- Schema 校验 → 失败重试 1 次 → 再失败降级规则版 Context（离线兜底）

### System 1 统一输出格式（所有建议）
```
[推荐1] 装备/海克斯名 —— 一句话理由（结合敌方构成/已选海克斯/身上小件）
[推荐2] ...
[推荐3] ...
```
加点只在 overlay 常驻态显示一行静态顺序（来自当前 `build_paths.skill_order`），不占 System 1 调用预算、不告警偏离。
调用时机与预算：首轮海克斯 1 + 出门装 1 + 每层海克斯 3~4 + reroll 重推 0~1 + 死亡刷下一件 2~3 + 事件简评 1~2 ≈ **每局 8~11 次，硬上限 15**。

## 3. 交互实现

| 机制 | 实现 |
|---|---|
| 生命周期 | LCU 阶段状态机（ChampSelect→GameStart→InProgress→EndOfGame）自动驱动，无热键；仅留一个可选 overlay 显隐键；秒退/掉线回大厅也走重置 |
| 海克斯界面检测 | **标题条小区域 OCR（每 2s）+ 229 海克斯库模糊匹配为主信号**：≥2 个标题命中 = 界面出现；连续 3 帧无命中 = 消失（迟滞防误触）。模板匹配（cv2.matchTemplate，几 ms）退为预热加速与 OCR 异常时兜底。OCR 认不出即暴露"改版/漂移"→ 提示重标定 |
| 海克斯记账 | **`keyboard` 库鼠标钩子（只读，不拦截不注入）**：参考项目已依赖该库做全局热键，Windows 实测可用，不新增 pynput。界面活跃窗口内，点击落点 = 卡片 A/B/C 矩形 → 记账"本轮已选 X"；台账常驻可见可纠错。兜底：50ms 轮询 GetAsyncKeyState + GetCursorPos |
| reroll 重识别 | ① reroll 按钮矩形纳入点击监听，点击立即主动重扫；② 界面活跃期间每 2s 比对卡片标题文本，内容变化即重启识别+推荐（双保险）；内容稳定 2 帧后才允许计入台账 |
| 首次采样标定 | 主窗口"开始标定"→ 海克斯界面出现时自动截屏 → 保存三个标题条位置、三张卡片矩形（含可点击区域）、reroll 按钮矩形 → 之后永久全自动。分辨率自适应沿用参考项目 REGIONS 百分比做初值；开发期可用界面截图离线预制 |
| 出门装触发 | 见 §2 状态机（首个海克斯记账后按装备状态分流） |
| 兜底 | LCU 断连 → 主窗口手动输英雄（拼音模糊匹配）；AI 失败/无 key → 规则模式 |

## 4. 模型双槽位（百炼，界面独立配置）

| 槽位 | 用途 | 默认模型 | 频率 |
|---|---|---|---|
| System 2 | ChampionContext 生成、语义标签库离线生成 | qwen3.8-max | 每局 1 次 |
| System 1 | 快照建议器（三选项+理由） | qwen3.8-flash（¥0.8/¥2.7 每百万 token） | 每局 8~11 次 |

每槽位独立配置：模型名（预置 + 自定义输入）、API Key（仅存本地 settings.json，可选读环境变量 DASHSCOPE_API_KEY）、base_url、温度、max_tokens、**测试连接按钮**。全局：AI 总开关、每局调用硬上限、费用仪表（本局/累计，单价可改）、超限或无 key 自动降级规则模式。任意 OpenAI 兼容平台均可换用。

**档位定义**：S/A/B 是"**先验 + 语境修正合成评分**"的分档，**不是胜率分桶**——与架构自洽，同时满足合规（不展示胜率数字）。

**成本**：~¥0.07~0.12/局，每天 10 把 <¥1.5。

## 5. 三层数据栈

| 层 | 内容 | 来源 | 作用 |
|---|---|---|---|
| A 统计层 | 核心装/鞋子/出门装登场率+胜率、海克斯排名、**加点顺序**、技能加点 | OP.GG（Selenium 沿用参考项目，天级刷新；P1 尝试 XHR 探针降级纯 HTTP） | 版本货币 |
| B 事实层 | 装备/海克斯属性、效果、语义标签（减疗/魔抗/爆发/流派亲和） | Data Dragon 元数据 + System2 离线打标（229 海克斯，增量更新） | 防幻觉 + 规则引擎依据 |
| C 战局层 | 敌方实时出装/KDA/阵亡态、我的装备与已选海克斯、**敌方威胁画像（伤害类型由英雄+装备推断——无 per-player 实时伤害数据）** | Live Client Data API（127.0.0.1:2999，5s 轮询；P0 首日 dump 实测字段） | 适配输入 |

出装推荐流程：候选集（按 §5.3 三类构造函数生成）→ 规则引擎按敌方构成打分（3 法师→魔抗↑，2 治疗→重伤↑）→ System1 在候选内给三选+理由 → 装备名必须过 DD 校验才输出。

### 5.2 层 0 确定性细则一：current_path（防路线漂移）

删掉流派卡后，"路线自然演化"必须由确定性状态机保证，否则 System 1 每次死亡都重新选路线会漂移（第 2 件出 AP、第 4 件推 AD）。

- `rules_engine` 从"已购装备 + 已选海克斯"按标签权重**确定性推断**当前路线（ap/ad/tank/特化），规则表来自 B 层标签；
- 快照显式携带 `current_path`，**System 1 只在该路线内给三选**，不重复做路线决策；
- 已购装备偏离当前 path 超阈值 → 规则层重定 path，overlay 显式提示"你这把在往 X 走"（提示，不拦截）。

### 5.3 层 0 确定性细则二：三类候选池构造函数

| 决策 | 候选池（层 0 生成） | 说明 |
|---|---|---|
| 出门装三选 | `ChampionContext.opening_items` 的 3 组 | 含"已选心之刚→巨人腰带"类联动 |
| 下一件三选 | 英雄 OP.GG 高频装 ∪ DD 通用抗性/功能件，**且必须落在 current_path 内** | 规则引擎按敌方构成打分排序候选 |
| 小件合成判断 | 身上已有组件 + `component_rules` | 合成 or 攒钱 |

System 1 只排序 + 写理由；候选外的装备名必须过 DD 校验才允许出现在理由里。

## 6. 资料库版本感知更新 + 新鲜度可见

1. 知道版本变了：LCU patch 号 + DD versions.json 每日检查
2. 知道内容变了：OP.GG 抽样校验（随机 3 英雄比对，差异→增量抓取）+ CommunityDragon 该模式海克斯定义集合 diff（P0 验证路径）
3. 执行更新：增量爬变动条目 → 语义标签只对新增项重生成 → 快照版本化 + GitHub 兜底
4. **新鲜度可见（v4.1 新增，对"版本翻译器"是底线）**：数据面板常显"数据版本 / 抓取日期"；抓取失败或 >7 天未更新 → 黄标"数据可能过期"；ChampionContext 请求外显数据版本号，杜绝"拿着三个月前的答案还不吭声"
