# P0 真机验证清单（代码已完成，以下需在真机执行）

> 离线冒烟已全绿（`uv run python tests/smoke_offline.py`，51 项断言，
> 覆盖状态机/出门装分支/触发器/路线推断；`HEXA_SMOKE=1 uv run python app.py` UI 可启动）。
> 以下条目无法离线验证，按顺序执行并勾选。

## 1. LCU 实连跟随（核心验收）

- [ ] 以管理员身份运行 `uv run python app.py`（LCU 读取进程命令行可能需要提权）
- [ ] 打开 League 客户端，主窗口阶段栏应从「待机」变化
- [ ] 进入大乱斗选人 → 阶段=「选人中」，自动识别我方英雄（骰子换人自动跟随）
- [ ] **确认 `get_both_teams()` 在 ChampSelect 阶段能否拿到敌方阵容**（ARAM 双方同时选；
      若 `enemyTeam` 为空，记录现象 —— GameStart 阶段 gameflow 会补全，属预期兜底）
- [ ] 进入加载 → 阶段=「加载中」，双方 10 人阵容显示，敌方威胁画像生成
- [ ] 进入对局 → 阶段=「对局中」，右侧 overlay 出现（F10 切换显隐）
- [ ] 打完/秒退 → 自动重置回「待机」（两种路径都要试一次）

## 2. fixtures dump（P0 计划交付：实测字段清单）

- [ ] `settings.json` 设 `"fixtures": {"dump": true}`（或首次运行后手动改）
- [ ] 完整打一局，结束后检查 `fixtures/{时间戳}-{英雄}/` 目录：
  - [ ] `lcu_*` 文件：champ-select session / gameflow session 原始 JSON
  - [ ] `live_activeplayer` / `live_playerlist`：每 5s 一份快照
  - [ ] `_fields.md`：自动汇总的字段清单
- [ ] **重点确认并记录**（写入本文件下方"实测记录"）：
  - [ ] `playerlist` 每个玩家是否含 `items[]`（设计假设，P1 敌方装备扫描依赖）
  - [ ] `activeplayer` 的金币字段名（`currentGold` / `goldTotal` 实测名）
  - [ ] `team` 字段值（`ORDER`/`CHAOS`）与敌我区分是否可靠
  - [ ] 死亡时 `isDead`/`respawnTimer` 是否及时反映
- [ ] **海克斯界面实测**（计划 P0.5 附带项）：记录每局海克斯轮数（白银/黄金/棱彩各几轮）、
      每轮出现的大致时间点、选择倒计时秒数

## 4. 方案制出装（AI 适配池）真机验证

System2 改为产出 2~4 个命名出装方案（流派制，非 ap/ad/tank 三键）；
System1 局内在全方案池内结合快照/海克斯权衡。真机重点确认：

- [ ] System2 日志 `方案N` ≥2：检查 overlay/日志中方案是否为真实流派分叉
      （同 path 多方案如"灼烧消耗流/金身流"与跨 path 方案并存）
- [ ] **对面 3 坦克局**：方案 items 是否自行出现破甲/百分比伤害件
      （破败/黑切/多米尼克/虚空之杖/兰德里等）且 note 写明理由——
      这是"针对方向交给模型"的核心验收，代码侧无任何名单
- [ ] **对面治疗系英雄 ≥2 局**：方案/局内建议是否自行出现重伤件
- [ ] 局内拿到的海克斯全偏 AP 时（AD 英雄）：下一件建议是否切到 AP 方案池
- [ ] System1 理由是否说人话且 ≤22 字（跨方案取件时理由是否成立）
- [ ] System2 失败/超时降级：日志"规则版上下文"后建议是否平滑回 OP.GG 序
- [ ] OP.GG 核心三件仍为锚：无特殊情况时 ①②③ 不被模型带偏成冷门件
- [ ] ctx 就绪瞬间：下一件建议自动刷新一次（日志 next_items 事件，
      主线切到方案池首件）；出门装态与满装态不触发该刷新
