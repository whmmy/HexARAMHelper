## 6. 海克斯 API 探针验证（2026-09-30 竞品调研发现）

> 背景（证据链见 [竞品对比报告_20260930.md](竞品对比报告_20260930.md) §1）：
> 竞品 ARAM-tool（E:\project\ARAM-tool）证明 Live Client Data API 可以读到
> 已选海克斯——`allgamedata` 返回 `allPlayers[].runes.generalRunes[]`，其中
> `id > 100000` 的条目即海克斯（ARAM-tool/lcu_client.py:640-665，作者仅用它
> 计数**自己**的海克斯数量，未提取名字、未碰敌方）；LCU `/lol-perks/v1/perks`
> 可做 id→名字映射（lcu_client.py:297-314）。本项目既定结论"海克斯 API 读不到"
> （实施计划"敌方海克斯暂缓"的前提）至少对自家英雄不成立——`live_api.py`
> 此前从未解析 runes/perks 字段。以下条目需真机对局中执行，结果决定
> 敌方海克斯功能是否解封。

- [ ] 自家 `generalRunes` 是否出现海克斯条目：id 形态、条目数是否随选择递增（0→3）
- [ ] `id > 100000` 启发式当前版本是否成立（有无例外：低 id 海克斯 / 高 id 普通符文）
- [ ] `/lol-perks/v1/perks` 映射能否覆盖这些 id 并返回海克斯名（对照 `augment_names.json`）
- [ ] **敌方 allPlayers 条目是否同样携带海克斯 id**（关键分叉，结果分叉见下）
- [ ] reroll 后 runes 是否即时更新（若是，可作点击记账"2s 内容比对"的旁证信号）
- [ ] 已轮询的 `/LiveClientdata/playerlist` 是否也带 runes 字段
      （若是则**零新增请求**，直接并入 live_api.py 解析即可）
- [ ] 打完整一局，与 OCR 台账逐条交叉比对，记录不一致案例（OCR 认错 / API 缺失）

**结果分叉**：
- 敌方可见 → "敌方海克斯暂缓"解封：ThreatProfile 直接获得敌方海克斯实证
  （数据直出喂模型，零 OCR 成本，符合"数据出事实"铁律）
- 仅自己可见 → 用作 OCR 台账交叉校验源：OCR 认错可自动纠正 + reroll 旁证

**探针脚本**（对局进行中任意时刻运行，无需 key；LCU 映射部分需客户端在运行）：

```python
# 临时探针：打印 10 人 generalRunes 中 id>100000 的条目
import requests, urllib3
urllib3.disable_warnings()
d = requests.get("https://127.0.0.1:2999/liveclientdata/allgamedata",
                 verify=False, timeout=2).json()
me = d["activePlayer"]["summonerName"]
for p in d["allPlayers"]:
    runes = (p.get("runes") or {}).get("generalRunes") or []
    augs = [r.get("id") for r in runes if (r.get("id") or 0) > 100000]
    tag = "  <- 我" if p.get("summonerName") == me else ""
    print(f"{p.get('team')} {p.get('championName')!s:12s} augs={augs}{tag}")
# id→名映射（port/token 来自客户端进程命令行 --app-port / --remoting-auth-token）：
# requests.get(f"https://127.0.0.1:{port}/lol-perks/v1/perks",
#              auth=("riot", token), verify=False)
```
